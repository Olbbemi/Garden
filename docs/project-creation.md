# 프로젝트 명명과 생성 기준

개인 GitHub의 모든 프로젝트는 Garden에서 목적, 범위와 이름을 논의하고 요청한 저장소를 생성한다.
Garden 내부 배치나 별도의 GitHub 조직을 전제하지 않는다.
이름을 정하거나 바꾸기 전에 이 문서의 명명 기준과 [기존 프로젝트 기록](projects.md)을 확인한다.

## 명명 기준

기준 문헌은 Kate Greenaway의 [Language of Flowers (1884)](https://www.gutenberg.org/files/31591/31591-h/31591-h.htm)다.
다른 문헌이나 현대 꽃말을 별도 합의 없이 혼용하지 않는다.

- 역할을 한 문장으로 정의하고 핵심 의미와 연결되는 꽃의 원문 이름과 꽃말을 직접 확인한다.
  기존 저장소와 중복되지 않고 읽고 입력하기 쉬운 이름을 고른다.
- 여러 꽃말은 전체를 기록하고 선정에 사용한 의미를 구분한다.
  품종과 색상의 한정,
  학명이나 축약명과 원문 이름의 대응을 기록한다.
  꽃말의 번역, 역할에 연결한 해석과 이름의 어원을 구분하며, 어원을 꽃말의 근거로 쓰지 않는다.
- 적합한 후보가 없으면 의미를 억지로 확장하지 않고 기준 변경이나 예외를 합의한다.
  기준 변경만으로 기존 프로젝트의 이름을 자동 변경하지 않는다.

## 프로젝트 생성

1. 목적, 용도, 관리 범위와 기존 프로젝트와의 책임 구분을 논의한다.

2. 명명 기준에 따라 후보와 근거를 제시하고 사용자 승인으로 이름을 확정한다.

3. GitHub 생성, 로컬 생성 또는 clone 중 요청한 범위를 확인한다.
   GitHub에는 소유 계정,
   정확한 이름과 공개 범위, 로컬 작업에는 목적 경로가 필요하다.
   설명과 초기 파일도 요청을 따른다.
   이미 합의한 조건과 승인은 재확인하지 않고 누락 사항만 묻는다.

4. 계정의 동명 저장소와 해당 로컬 경로의 기존 파일 및 저장소를 확인한다.
   충돌 시 덮어쓰거나 이름과 경로를 임의로 바꾸지 않고 실제 상태와 처리 방식을 합의한다.

5. 합의한 조건으로 `gh repo create`를 실행하고 요청에 포함된 로컬 생성, clone과 원격 연결을 수행한다.
   이름 논의만으로 생성하지 않으며, 요청하지 않은 clone, 구현 코드,
   전용 훅이나 설정을 일괄 추가하지 않는다.

6. 실제 소유자, 이름, URL과 공개 범위, 로컬 경로, Git 저장소와 원격 연결을 확인한다.
   일부 성공은 완료 범위와 남은 작업을 구분하고, 재시도 전에 기존 결과를 확인한다.

7. [프로젝트 기록](projects.md)에 이름 선정 근거와 생성 결과를 남긴다.
   이름 확정을 생성 완료로 표시하지 않는다.
   이후 구현과 전용 설정은 해당 프로젝트에서 진행한다.

공통 Git 훅은 Hortulanus 규약을 따르고 별도 설치 구조를 만들지 않는다.
이 절차는 운영 규칙이며, 사용자의 GitHub 웹 등에서의 직접 생성을 기술적으로 차단하지 않는다.

## 기록 항목

- 이름 선정: 저장소 이름과 역할, 원문 꽃 이름과 꽃말 전체, 선정한 꽃말과 번역,
  역할과의 연결 근거, 원문과 저장소 이름의 대응, 출처 URL과 항목 위치, 확정일,
  예외가 있으면 내용과 합의 근거.
- 생성 결과: 상태(`이름 확정`, `일부 생성`, `생성 완료`), 요청 범위, 생성일,
  확인 결과와 남은 작업.
  GitHub 생성 시 소유자, URL과 공개 범위를, 로컬 작업 시 저장소 경로와 원격 연결을 기록한다.
